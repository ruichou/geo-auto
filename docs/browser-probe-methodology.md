# 浏览器 GEO 探测方法

浏览器探测用于观察用户实际使用的 AI 产品界面，不等同于 API 模型结果，也不代表全体用户一定看到相同答案。

## 采样单元

每个样本固定记录平台、browser surface、原始问题、提示词、地区、语言、样本序号和实验批次。默认对同一问题独立采样 3 次。每次采样前重新进入平台的新对话首页，并在准备阶段和发送按键前两次验证回答节点数必须为零；无法证明为空时拒绝发送。成功样本保存 `fresh_context_verified`、隔离方法、发送前回答计数、纯站点 origin 和会话 URL 的 SHA-256，不保存可能含会话 ID 的完整 URL或 path。同批样本共享 `experiment_id`，但各自拥有唯一 `batch_item_id`。

## 恢复与边界

逐项清单先写数据库，再调用浏览器。成功项不会重发；失败项最多按 `monitor.max_item_attempts` 有界重试。登录过期或验证码会把平台标记为需要重新登录，不尝试绕过。浏览器批次不会被 API 恢复器误执行。

临时限制与登录失效分开处理。只读就绪诊断不会打开浏览器或擅自改写账号状态：限制尚未到期时标记为 `restriction_active`，到期后标记为 `retry_due`，仅表示下一次后台探测可以恢复尝试；时间戳缺失或无效时继续保持不可尝试。真正成功取得回答后才恢复为已连接并形成测量证据。

无论从每日流程还是单独执行 `browser-probe`，入口都会先运行 stale-batch watchdog：超过配置时限仍为 running 的清单项会转为可恢复失败，批次记为 interrupted，并保留诊断。

## 第二独立引擎

系统已加入 Kimi 网页版连接器。Kimi 官方产品页明确提供网页版并说明登录后可同步对话；连接器仅用于低频、重复、隔离会话的真实问题采样，不发布内容、不刷评价，也不把“已配置”当成“已有测量证据”。2026-09-05 对公开未登录页做了只读校准：确认 `www.kimi.com`、`/?chat_enter_method=new_chat` 新会话入口以及 `contenteditable` textbox。回答容器仍必须在首次登录后的校准采样中验证，失败时任务保留错误且不会写入空回答。

参考：[Kimi 官方产品页](https://www.kimi.com/products/)、[Kimi 官方新手指南](https://www.kimi.com/en/help/new-user-guide/overview)。

默认每次最多 6 次浏览器询问。探测只提出中立、可核查的问题，不要求模型强行推荐宏图商机汇，不发布内容，也不产生平台互动。

无人值守运行会在品牌与获客优先问题池中，优先选择浏览器样本更少、最后采样时间更早的问题，避免长期只测列表第一题。定向诊断可通过 CLI 精确指定问题；精确问题仍受样本数和整批调用上限约束。

## 解读

只有同一实验批次达到目标重复次数，系统才进入可见度、引用和竞品差距判断。少量样本只用于发现信号；措辞差异、界面实验、账户个性化、时间和地区都可能改变答案，不能把观察结果表述为因果提升或稳定排名。

“正面率”只在明确提及宏图商机汇的答案中计算；完全未提及时返回暂无数据。通用回答中的积极措辞不能被算作品牌正面评价。
