# GEO 差距行动协议

差距诊断必须同时保留“全量可追溯”和“当前可执行”两个视图。长尾问题数量大不代表应立即采样，否则会挤占核心品牌与获客问题的样本预算。

## 两层队列

- `actions`：所有问题的完整诊断，继续写入 `geo_actions` 和策略快照，用于历史追溯。
- `focus_actions`：控制台和运行报告中的聚焦队列。优先级为：
  1. `acquisition.priority_questions` 与品牌口碑目标问题；
  2. 已经拥有真实样本的长尾可见度、竞品、引用或叙事缺口；
  3. 核心覆盖未完成时，未采样长尾保留在 backlog，不占用聚焦位。

`monitor.focus_action_limit` 可限制聚焦队列长度，默认 20，但不会删除超出部分的完整诊断。

## 证据等级

- `unmeasured`：主口径没有样本。
- `insufficient_repeats`：有样本，但没有任一同批实验达到至少 3 个唯一样本位。
- `single_engine_preliminary`：至少一个引擎完成重复采样，但尚未达到配置的独立引擎数；只是初步诊断。
- `multi_engine_observed`：达到至少两个独立引擎的重复门槛，仍只表示观察结果，不证明因果。

重复门槛在差距诊断中硬性下限为 3，即使配置误填 1 或 2 也不会降低。同一批次中的重试只有占用不同 `sample_index` 才计入重复数。

## 执行边界

- 单引擎的“未提及”不得写成全网或全部 AI 不可见。
- 竞品候选必须先核验原回答和公开来源，不会自动晋升为竞品配置或品牌事实。
- 官网 ICP 阶段的 `recommended_next_step` 只允许补采样、复核和准备资产，不触发官网修改或内容发布。
- `build_gap_analysis(..., persist=False)` 用于控制台只读刷新，不会改写行动状态或时间戳。
